# 내 맛집 지도 — PRD 문답 기록

PRD 작성 전에 최소 10회 문답으로 기획을 다듬는다. 각 회차의 질문과 결정을 그대로 남긴다.

## 현재 만들어진 것 (2026-11-23 기준)
- 네이버 지도 저장 목록 2개(맛집리스트 895, 찐맛집 59) → 954곳 지도
- 상단: 검색 / 내 위치 / 지역 칩(도 → 시·군·구) / 유형 칩(포차·이자카야·회·갑각류·소고기·돼지고기 등 19종) / 🔥 이달 제철 / ⭐ 찐맛집
- 왼쪽 지도(전국 기본, 지역 누르면 그 지역만 확대) + 오른쪽 목록 (아이폰: 위 지도 / 아래 목록)
- 가게 상세: 별점·후기 수·한 줄 요약, 후기에서 많이 언급된 메뉴, 대표 메뉴·가격, 좋았던 점 키워드, 상호·주소·전화, 대중교통 예상 시간(거리 기반)
- 월별 제철 음식표(36종) → 제철 음식 카드 → 누르면 그 음식 파는 가게
- 네이버 플레이스 요약 주 1회 자동 수집(월 05:00), 4주 평균 별점·지난주 대비 새 후기
- 전화번호 없는 곳은 네이버 검색 결과에서 주소로 확인된 번호만 보강

## 1회차 — 사용자 · 사용 순간 · 플랫폼 · 데이터
- **주 사용자:** 나 + 친구·가족 몇 명 (공개 서비스는 아님)
- **사용 순간 (모두 해당):** 오늘 뭐 먹지 고민될 때 / 여행·출장 갈 때 / 제철이 바뀌는 시기 / 약속 장소 정할 때
- **플랫폼:** 웹 먼저(아이폰 홈 화면 추가), 반응 좋으면 앱
- **데이터:** 네이버 저장 목록 기준. 추후 일본 등 해외는 구글 지도 기반으로 끌어오기

## 2회차 — 공유 · 약속 장소 · MVP 범위 · 해외
- **공유:** 내 지도를 링크로 보기만 (수정은 나만)
- **약속 장소 (모두 필요):** 여러 명 출발지 중간 지점 추천 / 후보 몇 곳 골라 투표 / 조건으로 거르기
- **MVP 필수:** 제철 음식 → 가게 (구현됨) / 실제 대중교통 시간 (노선 기반)
- **2단계로:** 방문 기록·메모, 제철 알림
- **해외:** 미정, 후순위 (PRD엔 '향후 확장'으로만)

## 3회차 — 대중교통 · 투표 · 필터 · 제철 정확도
- **대중교통:** 네이버 기반 데이터로 계산하되, 네이버 앱/웹으로 넘기는 연결은 하지 않음
  - ⚠️ 확인 필요: 네이버 공식 API(NCP Maps)는 자동차 길찾기만 있고 대중교통 경로는 제공하지 않음 → 4회차에서 방식 결정
- **약속 투표:** 친구가 투표 링크에서 자기 출발지까지 입력 → 중간 지점 추천. 외부 API 연동 없이 단순하게
- **필터:** 휴무인 곳, 체인점 (4회차에서 '제외'인지 확인)
- **제철 태그:** 자동 분류만 (수동 수정 기능 없음, 틀리면 규칙을 고침)

## 4회차 — 대중교통 방식 · 필터 확정 · 투표 저장 · 공유 범위
- **대중교통:** 네이버 지도 내부 경로 계산을 받아와 앱 화면에만 표시 (네이버로 이동 없음)
  - 리스크: 비공식이라 막히거나 형식이 바뀔 수 있음 → 실패 시 거리 기반 추정으로 자동 대체
- **필터:** 그날 휴무인 곳은 후보에서 제외 / 체인점은 배지로 표시만 → 영업시간·휴무일 수집 필요
- **투표 저장:** 앱의 작은 저장소(투표·출발지만 저장). 친구는 이름만 입력
- **공유 범위:** 숨길 것 없음 (단, 내 출발지는 내 기기에만 저장되는 현재 방식 유지)

## 5회차 — 첫 화면 · 이름 · 디자인 · 제철 확장
- **첫 화면:** 내 주변 지금 갈 만한 곳 (내 위치 기준 가까운 + 영업 중 + 제철 표시)
- **서비스 이름:** 사용자 이름을 반영한 센스 있는 타이틀 3개 추천받기 (6회차에서 이름/닉네임 확인)
- **디자인:** 3개 시안을 모두 보고 결정 (iOS 기본 / 계절감 따뜻한 톤 / 지도 감성 강하게)
- **제철 확장:** 다음 달 미리보기, 이번 달로 제철 끝나는 음식 알려주기

## 6회차 — 이름 기반 · 중간 지점 기준 · 폐업 · 동기화
- **이름:** 내 네이버 닉네임 기반으로 작명 → 7회차에서 3개 중 선택
- **중간 지점:** 모두의 이동시간 합이 최소인 곳
- **폐업·이전:** 주간 수집 때 감지하면 알림만, 숨길지는 내가 결정
- **동기화:** 주 1회 자동 + 앱의 '지금 동기화' 버튼 (저장 목록 자체도 다시 받아 새 가게 반영)

## 7회차 — 이름 방향 · 성공 기준 · 비용 · 운영 위치
- **이름:** 해산물·날것(회) 좋아하는 취향을 살려서 다시 제안받기 (닉네임 기반 유지)
- **성공 기준 (모두):** 제철 추천으로 실제 방문 / 약속 잡을 때 실제 사용 / 친구가 먼저 링크 요청 / 네이버 지도 대신 이걸 먼저 염
- **운영비:** 무료. 수집은 내가 쓰는 데스크탑에서
- **운영 위치:** GitHub에 올려서 배포, 사용은 나만 + 링크만 공유

## 8회차 — 이름 · 저장소 공개 · 투표 DB · 동기화 버튼
- **이름:** 내 이름은 빼고 '날것' 느낌을 살린 작명 3개로 다시 → 9회차
- **GitHub:** 공개 저장소 OK (GitHub Pages 무료 배포)
- **투표 저장:** 무료 DB 서비스 하나 (Supabase 무료 플랜 권장: 가입 1번, 투표·출발지 테이블만)
- **동기화 버튼:** 폰에서 눌러도 '동기화 요청'을 남기고, 데스크탑이 켜지면 처리 (요청은 같은 무료 DB에 기록)

## 9회차 — 이름 확정 · 취향 반영 · 기준 위치 · 첫 화면 기준
- **서비스 이름: 「한 점」** (회 한 점, 생굴 한 점 — "오늘은 어디서 한 점?")
- **취향 반영:** 내가 자주 간 유형을 자동 학습해서 위로 → 방문 기록이 필요 (10회차에서 방식 결정)
- **기준 위치:** 현재 위치(GPS)
- **첫 화면 '지금 갈 만한 곳':** 이달 제철 메뉴가 있는 곳 (현재 위치에서 가까운 순)

## 10회차 — 방문 기록 · 알림 · 일정 · 추가 문답
- **방문 기록:** 앱에서 '갔다 옴' 버튼 (날짜만 기록) → 자주 간 유형을 학습해 추천 순서에 반영
  - 방문 기록이 MVP 취향 학습의 전제라 2단계에서 MVP로 올림 (버튼 하나 수준)
- **알림:** 앱 안 배지만 (푸시·카톡 없음)
- **목표 시점:** 12월 안 (겨울 제철 시즌에 맞춰, 범위는 작게)
- **추가로 다듬을 것:** 약속·투표 흐름, 제철 음식표 → 11회차 후 PRD 작성

## 2026-11-24 — 바뀐 결정 (Windows로 옮긴 날)
- **리뷰 수집:** 주 1회 자동 수집 폐지. 가게를 처음 저장했을 때 1번만 받고, 앱의 '동기화' 버튼을 누를 때만 새로 저장한 가게를 받는다 (6회차 '주 1회 자동' 대체)
- **찐맛집:** 개념 삭제. 자주 가는 곳은 방문 횟수 태그(1~4 / 5~9 / 10+ 금색)로 드러냄
- **방문 기록:** '갔다 옴' 대신 '방문 기록', 누를 때마다 +1, 가게당 메모 1개
- **로고:** 사용자가 준 손글씨 '한점' 이미지, 헤더 가운데

## 12회차 — 마무리 문답 (2026-11-24)
- **제철 범위:** 대표 메뉴만 (네이버 메뉴 앞 3개 + 후기 언급 상위 3개 + 가게 이름). 11월 284곳 → 187곳
- **폐업:** 앱에서 따로 표시하지 않음. 네이버 저장 목록에서 지우고 동기화하면 지도에서 빠진다
- **방문 기록·메모:** Supabase에 저장해 기기 상관없이 같게 (친구에겐 안 보이게). 배포 뒤에 진행
- **다음 큰 작업:** 배포 먼저 (GitHub Pages)

## 11회차 — 약속·투표 흐름 · 제철 범위
- **투표 후보:** 친구들 출발지가 모이면 이동시간 합이 최소인 내 저장 맛집 3곳 자동 추천
- **마감:** 정한 인원이 모두 투표하면 자동 마감
- **결과:** 같은 투표 링크가 결과 화면(가게·주소·전화·각자 가는 시간)으로 바뀜
- **제철 범위:** 해산물(중심) + 계절 요리 + 지역 특산 연결
